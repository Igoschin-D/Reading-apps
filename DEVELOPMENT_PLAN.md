# План разработки: мобильная читалка с универсальным форматом книг

## Идея проекта

Мобильное приложение (Android/iOS) для чтения книг. Ключевая особенность:
приложение умеет принимать файлы разных форматов (PDF, FB2, EPUB и т.д.)
и конвертировать их во **внутренний унифицированный формат**, который
дальше и рендерится в читалке. Это значит, что движок рендеринга/пагинации
пишется один раз и не зависит от исходного формата файла — новый формат
добавляется отдельным конвертером, а не переделкой всего приложения.

Стартуем с поддержки **PDF** на тестовой книге, дальше расширяем.

## Стек

- Язык: **Python**
- UI/фреймворк: **Kivy + KivyMD** (кроссплатформенная сборка под Android/iOS)
- Сборка: **kivy-ios** (iOS — целевая платформа, сборка только на macOS/Xcode);
  Buildozer (Android) — отложено, не в приоритете
- PDF: **PyMuPDF (fitz)** — извлечение текста, структуры (TOC), изображений, метаданных
- Хранение внутреннего формата: JSON-манифест + папка ассетов (изображения),
  упаковано в zip-контейнер с собственным расширением (например `.ubook`)

Стек можно будет пересмотреть, если на практике упрёмся в ограничения
(например, качество текстового рендеринга в Kivy) — фиксируем сейчас,
чтобы не терять время на выбор, но не считаем решение железобетонным.

## Архитектурный принцип

```
[PDF] --\
[FB2] ----> [Конвертер формата] --> [Внутренний формат книги] --> [Движок чтения / UI]
[EPUB] --/
```

- Каждый формат — отдельный конвертер с единым интерфейсом:
  `convert(file_path) -> Book`
- `Book` — единая модель данных (метаданные + главы + блоки контента)
- Движок чтения работает **только** с моделью `Book`, ничего не знает
  про исходные форматы
- Добавление нового формата = написать новый конвертер, не трогая
  остальное приложение

## Этапы разработки

### Этап 0 — Подготовка окружения
- Инициализировать структуру репозитория (папки: `app/`, `converters/`,
  `core/`, `assets/`, `tests/`)
- Настроить виртуальное окружение, зависимости (Kivy, KivyMD, PyMuPDF)
- Положить тестовую книгу (PDF) в проект для отладки

### Этап 1 — Дизайн внутреннего формата
- Определить модель `Book`: метаданные (название, автор, язык, обложка),
  список глав, оглавление
- Определить модель блоков контента внутри главы: заголовок, параграф,
  изображение, список и т.д.
- Определить формат хранения на диске (JSON + ассеты, упаковка в архив)

### Этап 2 — Конвертер PDF → внутренний формат
- Извлечение текста из PDF через PyMuPDF, склейка строк в параграфы
- Извлечение оглавления (если есть в PDF) и изображений
- Извлечение метаданных (название, автор)
- Обработка на тестовой книге, ручная проверка результата
- Известное ограничение на этот этап: сканы (PDF-картинки без текстового
  слоя) не обрабатываем — потребуют OCR, выносим в IDEAS.md

### Этап 3 — Движок чтения (рендер внутреннего формата)
- Загрузка `Book` из внутреннего формата
- Пагинация текста под размер экрана (реflow), учёт размера шрифта
- Базовая навигация: следующая/предыдущая страница, оглавление, переход
  по главам

### Этап 4 — Каркас мобильного приложения (Kivy/KivyMD)
- Экраны: Библиотека (список книг), Читалка, Настройки
- Импорт файла: выбор PDF с устройства → конвертация → сохранение
  во внутреннем формате → добавление в библиотеку
- Базовые настройки чтения: размер шрифта, светлая/тёмная тема

### Этап 5 — Прогон на реальной книге
- Полный цикл: импорт тестового PDF → конвертация → открытие в читалке
- Фиксация и исправление багов конвертации/рендеринга на реальном контенте

### Этап 6 — Сборка и запуск на устройстве
- Целевая платформа — **iOS**. Сборка через **kivy-ios** возможна только
  на macOS с установленным Xcode (кросс-компиляция под iOS с Linux
  невозможна в принципе — ограничение Apple, не инструментов)
- В этой среде разработки (Linux-контейнер) собрать и запустить iOS-сборку
  нельзя — этот шаг будет выполняться на Mac, когда до него дойдём
- Android/Buildozer — отложено, не в приоритете (см. IDEAS.md при желании
  вернуться)

### Этап 7 — Второй формат: FB2
- Конвертер FB2 → `Book` (FB2 — это XML, парсим через lxml)
- Проверка, что читалка отображает книгу без изменений в движке
  (валидация архитектуры: абстракция действительно работает)

### Этап 8 — Третий формат: EPUB
- Конвертер EPUB → `Book` (библиотека `ebooklib`)

### Этап 9 — Разбор бэклога
- Возвращаемся к [IDEAS.md](IDEAS.md), приоритизируем и добавляем
  фичи по одной: закладки, поиск по тексту, заметки, синхронизация,
  дополнительные форматы и т.д.

## Как работаем по плану

- Идём по этапам последовательно, каждый этап — рабочий результат,
  который можно потрогать (не переходим дальше, пока предыдущий этап
  не работает на тестовой книге)
- Новые идеи по ходу — в [IDEAS.md](IDEAS.md), не смешиваем с этим планом
- План можно и нужно корректировать по мере того, как что-то на практике
  оказывается не так, как ожидалось
